# Project Documentation

## 1. Overview

The assignment focuses on analyzing and designing a software system using object-oriented design principles. The work involved understanding the problem, identifying the required classes and their responsibilities, defining relationships between classes, and implementing the design.

## 2. Requirement Analysis

The problem statement was studied to identify the requirements of the system.

### Functional Requirements

* Identified the main features and operations required by the system.
* Determined what the system should be able to do.

### Non-Functional Requirements

* Identified requirements related to the overall quality and behavior of the system.
* Considered aspects such as maintainability, structure, and usability.

## 3. Class Identification

A noun-verb analysis was performed on the problem statement to identify potential classes and their behavior.

For each class, the following were considered:

* Data members
* Methods
* Data types
* Responsibilities
* What the class should know
* What the class should do
* What the class should not do

Both core classes and service/behavior classes were considered during this process.

## 4. Class Design

The identified classes were designed according to their responsibilities.

The main classes implemented include:

* `Screen`
* `Seat`
* `ShowSeat`

The classes were reviewed during implementation and modified where necessary.

## 5. Relationships Between Classes

The relationships between the identified classes were analyzed before implementation.

The appropriate relationships and multiplicities were determined based on how the classes interact with each other.

Aggregation was also included where required.

## 6. UML Diagrams

### Class Diagram

The class diagram represents:

* The classes in the system
* Their attributes and methods
* Relationships between classes
* Multiplicities
* Aggregation where applicable

The final class diagram was updated to accurately represent the implemented design.

### Sequence Diagram

A sequence diagram was created to represent the interaction between different objects during the execution of the system.

It shows the flow of communication between the relevant classes and helps explain how the system performs its operations.

## 7. Implementation

The designed classes were implemented according to the responsibilities identified during the analysis phase.

The implementation was reviewed against the class diagram to maintain consistency between the design and the code.

## 8. Testing

The completed implementation was tested using the available test cases.

The test cases were checked to ensure that:

* The implemented functionality works as expected.
* The classes interact correctly.
* The implementation matches the intended design.

## 9. Final Review

The complete assignment was reviewed after implementation.

The following were checked:

* Requirements
* Class design
* Class relationships
* Class diagram
* Sequence diagram
* Source code
* Test cases
* Documentation

The assignment was completed after the required implementation, diagrams, testing, and final review were finished.
